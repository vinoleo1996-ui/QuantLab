# 修正后宽篮的可重复性方案

写于 2026-09-29 22:56 CST，23:06 修订身份，23:15 补上四条启动前硬约束。这是正式协议，不是已跑完的结果。当前不启动账户、不改冻结路由器、不自动交易。`promotion_approved` 保持 false。

## 这份方案只回答一个问题

用成交额名次明确排序的宽篮，在五个调仓相位上是否可重复，以及中位成绩是否同时达到扣费年化 15% 和回撤 −33%。已有的 16.21% / −32.27% 是错误同档顺序的历史观察，不作为相位 0，也不作为基线。五个相位都出来之前，不接外部机制。

不回答：题材映射、新闻文本、仿真、L2 排序能不能再多赚钱。那些缺来源，而且顺序在本方案后面。

## 账户身份

下面每一条都固定。五个相位之间只允许调仓日不同。

- 池子：60 日成交额降序，名次 3001–5000，且 60 日成交额不低于 500 万元。先排名，再施加金额门槛；第 5001 名不回补进池。排名用的历史长度与 `scripts/extend_2018_band.py` 里已用的 253 个正成交额观测一致。成交额精确并列时，沿用该脚本已写明的代码次序，这只用于排名并列，不用于后面的持仓决胜。
- 2019-03-01 之前：池内同一档，没有财务分。名单按流动性次序交给选择器。
- 2019-03-01 及之后：沿用已经冻住的二元财务档，不重算财务通过与否。同一财务档内部按当天 `liquidity_rank` 升序。这个名次就是冻结加载器里的 `row_number() OVER (PARTITION BY trading_day ORDER BY adv_60 DESC, symbol)`。成交额精确并列时代码次序只用于这个名次，不另做一层决胜。
- 选择器仍是 50 只、前 150 名保留、每行业 15 只。排序键改为 `(-财务分, liquidity_rank)`。禁止用名单插入位置充当成交额顺序。现有 `select_band` 的插入位置决胜只在名单本身已按 `liquidity_rank` 排好时才等价；2019-03-01 之后的冻结名单不是这样排的。截面加载的最终语句是 `ORDER BY trading_day, symbol`，`build_signals` 再按低波特征值、然后代码插入字典。保留插入位置等于保留低波顺序。
- 每个决策日在同档名单里做一次检查：相邻两只的 `liquidity_rank` 必须非递减。出现更差名次排在更好名次前面，例如已指出的第 3042 名紧挨在第 3019 名之前，该日无效，相位停。
- 行业上限是申万行业，不是上市板块。本方案的相位实验不改这个上限。
- 费用函数与相位 0 目录里的 cost1 / cost2 相同。成本 2 倍只并列披露，不单独否决。
- 收益达标与回撤达标分开报告。收益达标是五个相位的成本 1 倍中位年化达到 15%。回撤达标是五个相位的成本 1 倍中位最大回撤不差于 −33%。旧协议里的 25% 回撤门留在旧 `protocol.json` 作历史，不删，也不用于本方案。−36% 不是达标线，也不放宽可接受回撤。

## 阶段 0：用成交额名次重建相位 0

1. 记录 `scripts/continuous_band.py`、`scripts/extend_2018_band.py`、`scripts/stable_book.py`，以及冻结截面加载器和 `unit_interval_ranks` 所在文件的 SHA-256。同时记录旧观察目录 `targets.json` 的哈希，仅作对照。
2. 在原相位 0 的决策日上准备名单。池子成员仍是名次 3001–5000 且金额达标。财务档只有在该行 `financial_available_at` 非空、且不晚于信号日 18:00 时才能使用。当前本地财务表不满足这一点，所以这一步停在 `blocked_data`，不跑成本 1 倍或成本 2 倍。
3. 新目标哈希若与 `output/continuous_band_2018ext_rankorder_20260929/targets.json` 相同，写 `BLOCKED.json` 并停。相同说明仍在使用旧的同档顺序。哈希不同只说明路径换过，不是排序正确的证明。
4. 每个决策日另写 `decision_audit.jsonl`。每一行至少包含：候选证券、`adv_60`、`liquidity_rank`、财务档、`financial_available_at`、选择顺序、是否入选。同档相邻名次必须非递减。缺任何一列，或只交了持仓名单，这一相位不能进入账户。
5. 记下新相位 0 全期和 2026 年各调仓日的交易所构成。这是身份指纹，不是优化目标。

财务时点补上之前，这一阶段不给出年化或回撤。它也不继承 16.21% 或 −32.27%。

## 阶段 1：五个相位

相位集合写死为 `0, 4, 8, 12, 16`，单位是交易日，不是自然日。

对相位 `p`：把相位 0 的每一个决策日，在同一交易日历上向后移动 `p` 个会话。移出 2026-09-22 的决策日记为省略，省略必须留在轨迹里，不能静默丢掉。移动后的那一天，用**当天**的成交额、历史长度和财务档重新生成名单，再交给同一个 `select_band`。

禁止两件事：

- 禁止把原决策日的名单原样用到四天、八天之后，再把这叫做新相位。那只是同一名单晚几天交易，回答的是执行延迟，不是调仓相位。
- 禁止 `sessions[p:]` 这种切片。旧 D2 v1 就是这样把五个相位切成了同一组目标。

相位 0 也按上一节重建，不复用旧目标。相位 4、8、12、16 在移动后的当天重算池子和财务档。新日期如果套不到与冻结财务档相同的时点规则，该相位写 `BLOCKED.json` 并停，不用行业名、概念首项或上一期名单填洞。

每个相位各跑成本 1 倍和成本 2 倍，共 10 本账。输出目录：

`output/corrected_band_phases_20260929/phase_<p>/cost<1|2>/`

每本账至少有 `targets.json`、`daily_returns.csv`、`summary.json`、`decision_audit.jsonl`。另有一份 `trace.json`。十本账、逐日审计和「新目标哈希不同于旧观察」都落盘之后，才允许写 `VERDICT.json`。写到一半的表不能用来挑选相位。

`trace.json` 的每一行同时写下：原决策日、移动后的信号日、实际使用的流动性快照日、实际使用的财务快照日、规则上的首个可成交交易日、账本里的首个成交日、越界省略原因。信号日 T 只能使用 T 日 18:00（Asia/Shanghai）当时已可得的数据；订单不在 T 日成交，最早进入下一交易日。停牌或涨跌停导致的更晚成交照实记在首个成交日，不能把规则上的下一交易日填成已经成交。

财务 `available_at` 为空时，不得用 `announced_on`、报告期或文件修改时间放行。本地 `financials.parquet` 已核验为 901,404/901,404 行 `available_at` 为空，2025 扩展快照同样全空。因此任何使用财务档的决策日，包括相位 0 沿用冻结 0/1 档，现在都是 `blocked_data`。五相位账户在这个缺口补上之前不启动。可以先落一份无账户的成交额名次审计，标明财务档因空 `available_at` 不能参加排序；这份审计不是收益，也不能充当基线。

`summary.json` 沿用现有账本字段：年化、最大回撤、回撤峰值日、谷底日、期末权益、成交笔数、费用、滑点、`account_checks_passed`。任一相位的账户检查失败，状态为 `technical_invalid`。任一相位的行情快照、名次或财务档重建失败，状态为 `blocked_data`。两种情况都使整组五相位无效，不把失败相位拿掉后用剩下的四条取中位数，也不打开阶段 2。

## 读法在开跑前写死

只看成本 1 倍的五个相位。成本 2 倍放在旁边，标摩擦是否把年化打到 15% 以下，不作为开关。

- 中位年化、中位最大回撤是这条规则的成绩。五个数里的最大值不采用。
- 年化极差定义为成本 1 倍五相位 `cagr` 的最大减最小，单位是百分点。回撤极差定义为五相位 `max_drawdown` 的最大减最小，同样是百分点。两个数分开算，不加成一个指标。
- **可重复**：年化极差 ≤ 5，且回撤极差 ≤ 5。可重复和达标是两列，分开写进 `VERDICT.json`。
- **收益达标**：成本 1 倍中位年化 ≥ 15%。低于 15% 写成未达标，不能称作达标。
- **回撤达标**：成本 1 倍中位最大回撤不差于 −33%。不放宽到 −36%。

判决按这个顺序，前一条已经命中就不再往下改结论：

| 五相位状态 | 结论 | 阶段 2 |
|---|---|---|
| 任一相位账户检查失败，或行情/名次/财务快照失败 | `technical_invalid` 或 `blocked_data`。不取剩余相位的中位数 | 不启动 |
| 年化极差 > 5，或回撤极差 > 5，或中位回撤差于 −36% | 相位敏感，或回撤已超出 −33% 这一类 | 只启动 `board_stress_no_refill_v1` |
| 极差都 ≤ 5，且中位回撤落在 −33% 与 −36% 之间 | 风险未达标。账户可留下，不换池、不改持仓数、费用或调仓间隔 | 不启动 |
| 极差都 ≤ 5，回撤不差于 −33%，中位年化 < 15% | 可重复，收益未达标 | 不启动 |
| 极差都 ≤ 5，回撤不差于 −33%，中位年化 ≥ 15% | 可重复且收益、回撤都达标。对外数字用中位和两项极差 | 不启动 |

最后一行成立时，外部机制停止。下一动作只是冻结规则、记录之后的信号和真实成交，不自动下单。单独未达到 15% 不打开阶段 2。

## 阶段 2：只有上一支判决把它打开时才做

只改一件事，名字 `board_stress_no_refill_v1`。对照对象是相位 0 的修正选择器，不是五个相位里最好的那本。

压力按上市板块计算，因为 2024-02-19 的补仓清掉了主板、补进了创业板和科创板；申万行业上限没有挡住这件事。板块分为沪市主板、深市主板、创业板、科创板。信号日 T 的 18:00 之前已经知道的日线才能用。

- 炸板率：该板块在当日名单里，最高价触及由昨收和涨跌幅规则推出的涨停价，而收盘没有封住的比例。
- 上涨广度：该板块在当日名单里，收盘高于前收的比例。
- 涨停价来自本地日线已有的昨收和板块涨跌幅规则，标记为 `rule_derived_limit`。这不是交易所炸板专表，报告里必须写明。
- 某个板块同时满足：有效样本至少 20 只，炸板率 ≥ 0.25，上涨广度 ≤ 0.45。这三个数写死，不扫描。
- 样本不足或涨停价推不出：该板块视为无压力，按原规则买。禁止把缺失填成 0。

行为：已经持有的股票照旧按前 150 名和行业上限保留，即使它所在板块有压力。压力板块只是不再接受新进入的名字。不在这一刀里同时卖掉已有持仓，不改总仓位，不改 50 只上限，不改调仓日历。

只跑相位 0 的日历，成本 1 倍和 2 倍各一本。和相位 0 对照：成本 1 倍年化更高，且最大回撤不比相位 0 更深超过 2 个百分点，才记为这一刀有增量。否则关闭 `board_stress_no_refill_v1`。关闭之后不自动改跑「卖掉压力板块」。那是另一份方案，不能用同一段历史接着试。

题材相对强弱不在这一刀里。没有覆盖全池、可以留证的映射之前，不加这个分量。

## 本方案明确不做

- 不续跑、不补齐 D2 v2 的剩余 4 个种子。
- 不做无账户的目标日预飞行来占用这条主线。
- 不把 15:30–17:50 的采集时钟再扩成新的测试。已通过的回归保持冻结。
- 不并行启动文本账本、MiroFish 动作日志、QuantMind 的 14 字段验收。
- 不向用户索要行情或新闻供应商。阶段 2 若被数据挡住，写 `blocked_data`，而不是换一个网页接口。
- 不复制 easy-stock、MiroFish 的源码。不使用它们的墙钟新鲜度、同 bar 开仓平仓、买卖评级、`stance`、`sentiment_bias`、`position_score`、`p³`、半凯利、TopkDropout 和止损。
- 不自动交易，不把 `promotion_approved` 设为 true。
