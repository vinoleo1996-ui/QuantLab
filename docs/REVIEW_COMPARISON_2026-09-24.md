```python
w_fac.to_frame('w').T.reindex([t])
```

转置行名为字符串 `w`，按照时间戳重索引会新建全NaN行，随后评分权重变0。专家IC、置信度虽在日志中变化，却没有实际传导至股票排名。因而以下因果解释均不成立：

- “平均动量IC为负，所以策略主动躲开AI牛股”；
- “低波专家权重0.35，说明低波专家驱动实际选股”；
- “关闭专家从14.62%降至13.61%，证明专家贡献约1pp”。

第三条实验同时改变了代码分支：专家分支在 `experts.py:177` 错把日期查到股票索引，拥挤过滤不执行；单专家分支 `engine.py:220` 会执行过滤，且方向反了。候选集合、排序和配权输入因此一起变化。这个开关实验没有隔离“专家预测信息”的作用。

存档确实从未持有300308和300502。这个持仓事实成立，基于IC压制的解释不成立。动态风险估计和止损仍在作用，所以评分失效不等于净值恒为零。

## 2. 同池29.03%能复现，但基准代码不符合其名称

exp1原样重跑：策略14.62%，池基准29.03%，所谓买入持有28.00%；与同事输出一致。我的首次报告没有完成同池对照，这是应补充的研究维度。

但“脚本确实输出了该数值”不能证明“这是按所述交易方式可实现的结果”。

### 月度等权仍然隐含每日再平衡

[exp1_reproduce.py:129](/Users/agiuser/Desktop/QuantLab/rev/exp1_reproduce.py:129) 每天用同一个 `w_exec` 点乘收益，权重不漂移，隐含每日再平衡且不记其成交费用。还复制了末日回退同日执行、缺失收益填零、隔夜与日内收益直接相加等问题。

此外，`active = close.loc[t_exec].notna()` 在假定开盘执行前使用了执行日收盘是否存在的信息。基准用完整代码索引、主引擎只用新候选索引，费用漏算行为也不完全相同。即使若干缺陷被双方共同继承，其误差也不保证互相抵消。

### “买入持有”也是固定权重日收益

[exp1_reproduce.py:141](/Users/agiuser/Desktop/QuantLab/rev/exp1_reproduce.py:141)：

```python
w = pd.Series(1.0 / len(codes), index=codes)
daily = ret.fillna(0.0) @ w
```

没有固定股数、现金、初始成交价格或费用。这是固定日权重收益公式。调用同事函数做三股等权反例，一只10→11→10，其余不动：

- 真正买入持有：0%；
- 同事的 `buyhold_baseline`：**+0.2020%**。

该基线还按全样本资格把后来上市股票包含在最初权重中，缺失时当0收益，不能视为起始日已买入这些股票。

### 29%不是“幸存者偏差量化值”

29%是一个事后选股池、特定有缺陷执行公式下的结果，其中混有市场/行业走势、股票选择和记账误差。需要在同一正确账户模型下，用历史可用池和今日快照池做对照，才能估计事后筛选影响。

因此可以说“现有策略输出明显跑输该脚本的同池对照”；还不能说“15%全由幸存者偏差提供”“偏差大概一半”或“真实预期8–12%”。当期市值最大的公司也不必然都是历史涨幅最大的公司，初始规模、发行股本变化等同样影响市值。

## 3. “开盘对收盘仅差0.2pp”没有排除记账错误

[exp3_variants.py:191](/Users/agiuser/Desktop/QuantLab/rev/exp3_variants.py:191) 的“收盘执行”使用：

```python
r_seg.iloc[0] = c2c[d0] @ w_exec - fee
```

如果确实在d0收盘才换仓，d0昨收至收盘的损益应属于旧仓；代码却使用新仓，给予了尚未持有时的全天收益。它不等于正确的收盘成交对照。

两个版本共享固定权重、末日时序等问题，输出接近只能描述这两条公式在样本里的差异，无法排除缺陷，也无法估计它们相对于正确账本的总误差。

独立反例已在首次审查中复现：整组换仓记0费用、缺失行情后跌幅被吞、卖不掉却继续买造成123.33%仓位、跌停止损仍成交、选股失败整月收益归零。股票池收益高与引擎有错误可以同时成立。

## 5. 合并后的行动优先级

1. **保留同池对照要求**，但先用现金/持仓单位守恒的共同引擎重建基准；分别定义买入持有、月度等权和历史波动匹配。
2. **评分失效必须列为P0**，修正engine与monitor的索引，加入常数替代/因子符号扰动和权重缺失门禁。日志存在因子权重不等于它已参与决策。
3. **修账户、成交与时序**：持仓漂移、旧新仓并集、冻结卖出、资金约束、缺口估值、最后一天待执行、无信号日损益。
4. **修数据新鲜度、腾讯字段退化和日度风控**，记录分项触发原因，不能只观察最终仓位推测功能工作正常。
5. **完成历史可用池与样本外对照后再谈收益**。目前可以确认模型未证明其选股价值，并已跑输一个需进一步修正的同池对照；真实Alpha和实盘年化未知。
