2. 代价：修好门禁的同时，把预注册实验打死了

这是本轮最需要你处理的一件事。

上一轮唯一的实证产出是 scripts/random_basket_audit.py 那个 200 次配对的零假设实验（观察组年化 4.54%，MC p=0.3035，无显著优势）。这个实验现在跑不动了。

证据链，每一环都实测过：

① candidates_a.parquet 列 = [code, name, price, open, high, low, mktcap, float_mktcap,
                            amount, volume, turnover, pct_chg, source]
   → 没有 sector 列

② cached_proxy() 第 45 行：实测 40 条记录，sector 分布 = {'UNKNOWN': 40}
   sector = spot.loc[c,"sector"] if ... and "sector" in spot else "UNKNOWN"

③ 第 75 行：cfg.portfolio.max_sector_weight = .30

④ engine.py:295：
   industry_policy = "disabled_diagnostic" if diagnostic and max_sector_weight==1 else "verified"
   → diagnostic=True 但 0.30 != 1，实测取到 'verified'

⑤ allocation.py:13-15：missing 非空且 policy != 'disabled_diagnostic'
   → return empty, 'industry_coverage_insufficient'

⑥ engine：if status != "ok": allocation_issues.append(...); cancel_buys(status); continue
   → 每次调仓都被跳过

⑦ 实测第 60 日敞口矩阵形状 = (1, 27)，行名 = ['UNKNOWN']，行和 = 27.0

结果是：观察组和 200 次零假设会全部产出空仓，observed.pkl 的旧结果（4.54% 年化）与当前代码不再可比。15:19:12 冻结的那份 reproduction/ 副本仍然能复现旧结果，所以预注册契约本身没有被破坏——但仓库里活着的代码已经无法重跑它。

怎么修。门禁的行为是对的（宁可具名拒绝，也不要静默降仓），问题出在 random_basket_audit.py:75 这一行自己把逃生开关堵死了：

  • 选项 A：把该脚本的 cfg.portfolio.max_sector_weight 设为 1，让 disabled_diagnostic 生效。语义正确——诊断场景本来就没有行业约束，把它设成 0.30 是假装有约束。
  • 选项 B：给诊断代理注入真实的行业映射，不再回落到 "UNKNOWN"。

无论选哪个，都是对预注册规格的修改。脚本第 96–97 行已经支持「规格变更写入新契约文件而非覆盖旧契约」——必须走这条路，否则预注册这件事就白做了。

问题状态说明
