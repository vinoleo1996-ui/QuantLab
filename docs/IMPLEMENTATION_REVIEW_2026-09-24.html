三、致命问题：预注册对照实验跑不出有效结论

上一轮你纠正过我：对照实验必须匹配持仓数、资金、费用、风险控制和可交易条件，而且不能从「没超过第 90 百分位」推出「池子里没有 alpha」。scripts/random_basket_audit.py 把这些话几乎逐条写进了预注册契约——does_not_test 字段直接写着 "absence of all possible alpha or superiority of another universe"，trials < 200 直接抛错，契约在评估之前落盘，规格变更另存新文件而不覆盖。方法论上这是对的。

问题是它跑不出有效答案。目录里只有 preregistered_contract.json，没有 summary.json／trials.json／observed.pkl——实验预注册了但没跑。我做了非破坏性探针（只调 cached_proxy() 和 prepare()，不写任何文件、不跑 200 次试验），结果如下。

四、其余未解决问题

4.1 数据层与引擎结构不兼容 P0

sources.py 里 open_status、quality_status、available_at、revision、reference_price 的出现次数全部为 0。新引擎的 trade_permission 只认 open_status == "trading"。也就是说：在生产路径上，每一根 bar 都会被判为 unknown_or_halted_open，一笔都不会成交。

目前唯一让引擎动起来的是 cached_proxy() 里那行乐观赋值 np.where(p.open.gt(0), "trading", "unknown")。契约里诚实声明了 "opening tradability approximated"，但生产数据源必须补齐这些字段，否则新引擎等于没有入口。

4.2 股票池仍是事后快照 P0

candidates_a 是今日实时快照（2074 行，索引含 300308/300502 等）。manifest.universe_coverage = "snapshot_research" 是标注，不是修复。MarketDataset.validate() 也接受 snapshot_research 作为合法值——它只要求你诚实贴标签，不强制历史可用池。

这不算错（诊断用途需要明确标记），但要清楚：幸存者偏差问题一点没动，universe_at() 里的 PIT 逻辑（asof_records + listing_date + 20 日 ADV）目前没有真实数据可以验证。方案「第二关：对照有效」过不了。

4.3 数据集清单不存在 P0

load_dataset 在 cli.py 里已被调用，但它需要 data/research/manifest.json——该文件不存在。data/bench/、data/fundamentals/ 为空。因此：

  • python -m quantlab.cli backtest 现在必然返回 blocked_result。这是设计上正确的拒绝，但也意味着目前没有任何合法路径产出研究结果。
  • known_panels()、persist_run()（在非 CLI 路径）、walk_forward_splits()、expert_top_union() 均无调用点。

4.4 遗留红灯测试 P1

tests/test_smoke.py:105 test_engine_run 构造 dict 形式的 panels 后调用 eng.run(panels, meta, bench)，断言 len(nav) > 0。而新 Engine.run() 对非 MarketDataset 输入故意返回 blocked_result。结果：24 个测试 1 个失败。

这不是引擎的 bug，是测试没跟上设计。tests/fixtures_v2.py 和 tests/test_replay.py 是 15:13 新加的（方向正确），test_engine_run 是没清掉的旧用例。红灯留在仓库里会腐蚀「测试全绿」这个信号，建议直接删除或改写成 v2 契约。

4.5 专家权重在噪声上过拟合 P1

experts.py 里 q = 专家组最近 12 期的组内平均 IC，然后 tau = max(np.std(q), 0.015)、w_exp = softmax(q/tau)。

本池 n=40，单期 RankIC 标准误 ≈ 1/√39 ≈ 0.16；12 期均值的标准误 ≈ 0.16/√12 ≈ 0.046。也就是说两个专家 q 相差 0.04 只是约一个标准误的差别，而 tau 被下限锁死在 0.015，会把 0.04 的差放大成约 14 倍的权重比（exp(2.67) ≈ 14.4）。

结论：专家权重几乎总是塌到单一专家身上，而这个「塌」是噪声驱动的。上一轮我们争论「低波专家权重 0.35 是否驱动了选股」，现在权重确实传导了，但传导的是一个统计上不可分辨的信号。这不影响正确性，但会让「专家贡献 X pp」这类归因再次不可信。建议把 tau 与 IC 的标准误挂钩，或者直接对 q 做收缩（shrinkage）。

六、按优先级排序的行动清单

#动作级别理由
1git init + 提交当前快照，之后每次 review 绑定 commit hashP0没有版本控制，任何结论都不可追溯。这是所有其他工作的前提。
2修 cached_proxy() 的行业缺失（注入真实 sector，或诊断运行显式设 max_sector_weight=1.0）P0不修则 55% 调仓失败，随机篮子对照实验没有任何检验力。
