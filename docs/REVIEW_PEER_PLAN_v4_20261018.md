## 2. v4 相比 v3 的改进

### 2.1 新增 Phase 4.5：外部算法拆解（最有价值的新增）

| 对象 | 类型 | 可复现层级 | 预期产出 |
|---|---|---|---|
| Microsoft Qlib | 开源代码 | 代码级 | Alpha158/360 特征 + LightGBM 模型 |
| Alpha101/Alpha191 | 公式库 | 公式级 | 10-15 个有经济机制的子集 |
| AQR/Acadian/MSCI | 方法论 | 方法论级 | 价值/质量/低波/拥挤逻辑 |
| 华泰/天风/国泰君安 | 因子报告 | 公式级 | PIT 可用、经济机制清楚的子集 |
| High-Flyer/Ubiquant | 专有基金 | 背景级 | 拥挤/AI 风险，不复现收益 |

**评估**：这是从"读论文"到"拆代码"的关键升级。Qlib 的完整代码可读，但 Alpha158/360 与我们的 panel 结构不同，直接复现有适配成本。

### 2.2 新增 H5：外部专家复现与集成

- H5a Qlib（技术面外部对照）
- H5b Alpha101/191 子集（公式级）

- 集成规则：固定等权 rank average，不优化权重

**风险**：Qlib 在全样本上调过参数，直接复现可能过拟合。必须 rolling train + 预注册 + 同池对照。

### 2.3 新增鲁棒性记分卡

7 维度记分卡（CAGR、MDD、稳定性、Alpha、胜率、交易、容量），胜率只做诊断。

**纪律正确**："不为了胜率加止损、不加择时、不换样本。"

### 2.4 时间线更现实

| 版本 | 总时间 | 10-30 前承诺 |

## 3. 关键技术评估

### 3.1 外部算法拆解的可行性

| 算法 | 难度 | 预计时间 | 关键障碍 |
|---|---|---|---|
| Qlib Alpha158 | 中 | 1-2 天 | 特征定义不同，需映射到我们的 panel |
| Qlib Alpha360 | 中 | 1-2 天 | 同上 |
| Qlib LightGBM + TopkDropout | 中 | 2-3 天 | 模型超参数、组合策略需适配 |
| Alpha101 子集 | 低 | 1 天 | 公式公开，但需 PIT 验证 |
| Alpha191 子集 | 低 | 1 天 | 同上 |
| AQR 风格 | 低 | 0.5 天 | 无代码，只拆逻辑 |

**总评估**：Phase 4.5 的 2-3 天是合理的，但"代码级拆解"要求读 Qlib 的完整相关模块（~5000 行），实际可能需要 3-4 天。

### 3.2 H5 集成的过拟合风险

固定等权 rank average 可以缓解过拟合，但如果单个专家已经在全样本上调过参数，集成后的"样本外"可能是伪样本外。

**建议**：
- H5a 的 Qlib 专家必须明确使用 rolling train（每年 refit），不能用全样本拟合
- 训练期固定为 2018-2022，2023-2026 才是伪样本外
- 如果 Qlib 专家的 ex-2025 收益 < 基线，直接关闭，不调参

### 3.3 执行现实性仍是最大短板

v4 仍然把"执行现实性"放在鲁棒性第一层（正确），但 Phase 2 的实现细节中有几个风险：

1. **ETF 去 ffill 可能改变 NAV**：如果去掉 ffill 后 ETF 缺失日导致调仓 blocked，NAV 会改变（之前用旧价成交，现在不成交）。这需要重跑并记录差异。
2. **T+1 开盘模型**：当前回测用的是 next-open 还是 close？v4 提到"next-open 模型可能过于乐观"，但没有明确说当前代码用什么。
3. **ST 涨跌幅 10%**：2026-07-06 后的变化，但当前代码是否已建模？

## 6. 风险与建议

### 6.1 最高风险：git 历史含明文 key

`65d8719` 提交了两个真实 API key。即使代码已修复，历史提交中仍有明文。

**选项**：
- A. 不 rewrite 历史，只轮换 key（用户去控制台重置 key）
- B. `git filter-repo` 或 `git rebase` 移除历史中的 key（会破坏 commit hash，影响所有基于该提交的工作）

**建议 A**：先轮换 key 让旧 key 失效，历史不 rewrite（避免影响 parallel sessions 的引用）。

### 6.2 第二风险：Phase 2 串行依赖

Phase 2（停牌分类）→ Phase 2.5（增量合并）→ Phase 3（前向引擎）必须串行。
如果对方在 Phase 2 上延迟，10-30 可能来不及。

**建议**：今天完成 Phase 2.5 剩余工作，明天做 trial merge，然后等对方完成 Phase 2。

### 6.3 第三风险：H5 外部专家的过拟合

Qlib 在全样本上调过参数，直接复现可能高估收益。

**建议**：H5a 只作为技术面对照，不做主 alpha；必须通过 rolling train + 同池对照才进入 Stage B。
