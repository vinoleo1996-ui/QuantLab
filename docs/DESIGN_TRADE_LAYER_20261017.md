# 买卖决策层设计：预测 → 凸优化 → 执行

（2026-10-17 CST。设计稿，未预注册；P5_I 待 P5_G 跑完后登记。）

## 1. 问题拆成三层，不要混在一起

| 层 | 回答什么 | 现在的做法 | 问题 |
|---|---|---|---|
| 预测 | 未来 20 日谁涨得多 | GBDT / 线性 / 随机 | IC 0.026，已到边界 |
| 配置 | 给定预测，应该持多少 | 固定 50 只等权、20 日换 | 机械、换手高、无成本权衡 |
| 执行 | 怎么买卖、买多少 | T+1 开盘、1% 参与率 | 无最优执行 |

用户说的“买卖策略”是第 2 层。它确实是凸优化问题，而且不需要新 alpha 就能改善。

## 2. 数学形式（凸）

给定预测收益 μ、协方差 Σ、当前权重 w0、成本 c：

```
max_w   μ'w − λ w'Σw − c'|w − w0|
s.t.    Σw = gross
        0 ≤ w_i ≤ max_weight
        行业权重 ≤ cap
        |w − w0| 的换手 ≤ turnover_cap
```

- 目标函数是凹的（μ'w 线性，−λw'Σw 凹，−c|Δw| 凹），约束线性 → **凸 QP**。
- 50 只股票，cvxpy 求解 <100ms；每天跑一次完全可行。
- 成本项让优化器自己决定“值不值得换”：预测改善小于成本就不动，这就是 no-trade band，不需要手写阈值。
- 这和 Gârleanu & Pedersen (2013) 的“部分调整”是同一个解；方案甲的滞后进出是它的启发式近似。

## 4. 小模型放在哪

- **不要**用一个小模型直接输出“买/卖”动作——那是把预测、配置、执行混成一个黑箱，样本 8 年、50 只，学不出来。
- 小模型只做**预测**：24 个特征 → 20 日收益（ridge / 2 层 MLP / 现有 GBDT），输出 μ。
- 凸优化器做**配置**：μ + Σ + 成本 → 目标权重。
- 执行层做**下单**：目标权重 → 次日开盘的订单。

这样每一层可单独验证：预测看 IC，配置看换手与净收益，执行看滑点。

## 5. 可验证的假设（P5_I）

- 同一套 GBDT 分数、同一个池、同一成本，把“20 日固定换 + 方案甲滞后”换成“每日凸优化 + 成本项”。
- 预期：换手从 2.95x 降到 1.5–2.5x，净收益 +0.2–0.5pp；回撤不变或略好。
- 门槛：成本 1 倍净 ≥ 方案甲 +0.3pp；成本 2 倍 ≥ 方案甲 +0.3pp；换手 ≤2.95x；MDD 不差于 −36.6%。
- 先验：中。优化器是标准件，但本仓旧主线用过同类方法且未过门槛——那次是信号/池子的问题，这次在同一 GBDT 分数上做对照，能分清是优化器无效还是信号无效。

## 6. 不要期待的事

- 凸优化不创造 alpha。μ 的 IC 还是 0.026，优化器只能把同样的预测做得更省成本、更平滑，不能把 2pp 变成 5pp。
- 如果 P5_I 只多 0.2–0.3pp，那它就是“把机械调仓变得可接受”的工程改进，不是收益革命。
- 真正要把收益推上一个台阶，还是池子（P5_G）和资产配比（G0），不是买卖点。
