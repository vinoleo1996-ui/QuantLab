一、分歧点逐条裁决

1.1 争议核心：引擎有没有核心 bug？

P0 同事 A 的 F01 —— 我完整复现，并且比 A 描述得更严重

根因在 quantlab/backtest/engine.py:184（monitor.py:107 同一处）：

w_row = w_fac.to_frame("w").T.reindex([t])   # 行索引是字符串 "w"，不是时间戳

实测输出：

w_fac.to_frame('w').T.reindex([t]) -> 全 NaN?  True
行索引变成: [Timestamp('2026-08-31 00:00:00')]   (原为字符串 'w')

然后 scoring.py:117 的 .ffill().fillna(0.0) 把权重全填成 0，于是 composite_score 恒为全 0 面板；experts.py:100 的 s.rank(axis=1, pct=True) 在全 0 面板上退化成常数 20.5/40 = 0.5125；expert_top_union 的 sort_values(ascending=False) 在同分序列上返回一个由 quicksort 内部顺序决定的伪随机名单。

我挂上探针重跑整段回测，结果如下——这是本轮审查最硬的一条证据：

同事 B 由此推出的三条因果解释，全部不成立

同事 B 的说法裁定依据
"池内动量类因子全样本 IC 普遍为负，动态 ICIR 压掉动量暴露，所以策略主动躲开 2024–26 的 AI 行情" 错 得分是常数，ICIR 从未传导到排名。持有的股票与 IC 无关，只与代码字符串排序有关。
"专家权重均值 lowvol_quality 0.35 > value 0.26 … 说明系统主动躲开 AI 动量" 错 专家权重只被写进日志。comparison.json 已证：把专家换成常数 0.5、权重固定动量 100%，逐日收益与持仓权重差为 0。
"去掉专家集成 13.61% → 专家集成确实贡献 +1pp" 错 这个开关同时切换了代码分支：专家分支走 expert_top_union（拥挤过滤因索引 bug 从不执行），单专家分支走 engine.py:220（拥挤过滤执行，且方向反了）。变量没被隔离。

换句话说：同事 B 观察到的"持仓事实"（从未持有 300308 / 300502）是真的，但它给这个事实配的机制是编的。

1.2 争议核心：同池 29% 基线，是"幸存者偏差量化值"还是"脚本口径错误"？

关键 两边各对一半 —— 我用严格 share/cash 账本做了仲裁

同事 A 的反例（3 只等权，一只 10→11→10）我原样复现：引擎公式给 +0.202020%，真实买入持有 0%。数学上 A 没错。

但 A 由此推论"29% 被这个口径错误实质性抬高"——这个推论错了。我把同池基线用持股数 + 现金 + 双边成本的严格账本重算：

但同事 B 的 "买入持有 28.00%" 是明确错的——真实买入持有是 32.62%。它那个函数叫 buyhold_baseline，实际算的是每日再平衡等权。同事 A 这一点抓得准。

无论用哪种口径，同池被动收益都远高于策略，"策略跑输自己所在的池子"这个结论是稳健的：

1.3 争议核心：年化 15% 是怎么来的？

两边都没说全 —— 我补一个决定性的发现

同事 A 说"14.62% 与存档 15.25% 的差异来源尚未定位"；同事 B 说差异来自缓存更新。我定位到了：

基准序列年化最大回撤gross=0.3 的期数
bench=None（退化为候选池均价，engine.py:149）14.6178%−17.7972%6
单调上涨的合成基准（regime 永不触发深熊）15.2515%−16.5197%0
候选池等权归一化指数15.1570%−19.5667%11
存档 results.pkl15.2515%−16.5197%0

存档的 15.2515% / −16.5197% 被精确复现，条件是 gross_scale ≡ 1.0（regime 从不触发深熊降仓）。而 data/bench/ 是空的，存档没保存基准序列——用代码里写明的退化路径（候选池均价）会触发 6 次深熊降仓，年化掉到 14.62%。

所以：15.25% 不是缓存漂移造成的，是"存档当时用的那条基准恰好没触发风控"造成的。同一份代码，换一条基准序列，年化在 14.62%–15.25% 之间，回撤在 −16.5%–−19.6% 之间。这本身就是"结果不可复现"的直接证据。

二、两份 Review 都漏掉的第三个事实

退化之后的"策略"，是一只跨 73 期恒定不变的 28 只篮子

因为得分是常数，expert_top_union 每期从同一批代码里挑出同样的 28 只：

所谓"月度调仓多因子选股"，实际是：一只固定的 27 只股票篮子 + 每月用 120 日收益跑一次最小方差配权 + 目标波动率降杠杆 + 回撤降仓。横截面因子选择、ICIR 加权、五专家集成、拥挤惩罚——全部没有参与决策。

而且这只篮子对池成分极度敏感（因为同分排序的 tie-break 是 quicksort 内部顺序）：

池的微小改动年化候选集重叠

而候选池是每日刷新的实时快照（cli.py:33-37 → sources.py:85 → 新浪 spot）。也就是说：今天跑和明天跑，只要 TOP40 名单动一只，就是另一只篮子、另一个年化。"15% 年化"不是策略的产出，是某一次 tie-break 的产出。

四、结论

对同事 A 的评价

技术结论成立，且是本轮唯一抓到决定性 bug 的一方。F01 是 P0 级真缺陷，我逐位复现（12.8779% vs 它报的 12.88%）。F02/F04/F05/F06/F08/F09 的机制我都验证过，成立。它自己的 review_audit.py 产出的确定性反例（全换仓 0 费用、缺行情吞跌幅、卖不掉继续买造成 123.33% 仓位、跌停止损仍成交、选股失败整月收益归零）与我的独立重跑一致。

两处过度：(1) 把同池 29% 的口径问题说成实质性高估——真实月度等权是 28.43%，几乎一致，它的反例虽然算术正确但量级误导；(2) 低估了 F01 的实际破坏力——它说"同分排序没有稳定性保证"，但没量化出"候选集跨 73 期恒定"和"池宽 ±1 就换篮子"这两件事。

对同事 B 的评价

方向对，机制错，结论过度。它把注意力放在"收益溯源"上，正确识别了幸存者池（这是 A 的第一版漏掉的维度，值得肯定）、腾讯源冻结、风控未触发、信号滞后（signals.json 信号日 2026-08-31 / 执行日 2026-09-23，我确认无误）。

但它整个因果解释建立在"因子和专家在正常工作"这个前提上，而这个前提是假的。它给的"动量 IC 为负 → 主动躲开 AI 牛股"、"低波专家权重 0.35 驱动选股"、"专家贡献 1pp"，全部是从日志里的数字反推的故事，而日志里的数字从未参与决策。它的"8–12% 实盘预期"没有任何证据链。

一个可操作的判据：如果 B 的结论成立（引擎干净、只是池子有偏），那修复方向应该是"换 PIT 池"；但真实情况是引擎的选股层根本没运行——先换池子毫无意义，因为选股结果不取决于池子里的股票，而取决于池子里代码字符串的排序 tie-break。
